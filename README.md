# FinAgent

공공·공개 데이터만으로 만든 매크로 대시보드입니다. 내 컴퓨터에서 Streamlit
서버를 띄우고(127.0.0.1) 브라우저에서 미국·한국·글로벌 매크로 지표를 한 화면에
보여줍니다. 화면까지 모두 Python으로 작성되어 있습니다. 선택 기능인 S&P 500
스크리닝과 포트폴리오(유명 투자자 13F 포함)만 예외로 yfinance·SEC 데이터를 받아
파일로 저장합니다(아래 참고). 대시보드에서는 금 선물 시세 하나만 yfinance로 받고,
그 캐시를 `data/macro/.yfinance/`에 둡니다.

A local macro dashboard built only on public and open data (FRED, U.S.
Treasury, New York Fed, Bank of Korea ECOS, ECB, BIS, OECD). It serves a
Streamlit page on `127.0.0.1` and keeps everything it fetches in memory.
The optional S&P 500 screener and portfolio pages are the exceptions: they
use yfinance (and SEC EDGAR/OpenFIGI for 13F filings) and save files under
`data/screen/`, `data/portfolio/` and `data/investors/`. On the dashboard only
the gold futures price comes from Yahoo through yfinance, whose caches go
under `data/macro/.yfinance/`.

## 설치와 실행

Python 3.12 이상과 [uv](https://docs.astral.sh/uv/)가 필요합니다.

```bash
uv sync                      # 이 폴더의 .venv에만 설치합니다
source .venv/bin/activate    # 이 폴더의 가상환경을 켜면 macro 명령을 쓸 수 있습니다
```

무료 API 키 두 개를 발급받습니다.

- FRED: <https://fredaccount.stlouisfed.org/apikeys>
- 한국은행 ECOS: <https://ecos.bok.or.kr/api/#/AuthKeyApply>

키는 환경변수로 넣거나, 이 폴더의 `.env` 파일에 적습니다.
이 폴더에 두는 파일은 `.env`(키, 앱은 읽기만 함)와 `finagent.settings.json`(보기 설정, 아래 참고) 두 개입니다. 스크리닝을 갱신하면 `data/screen/`도 생깁니다. 포트폴리오를 만들면 `data/portfolio/`, 유명 투자자 13F를 받으면 `data/investors/`도 생깁니다. 금 시세를 받으면 yfinance 캐시 `data/macro/.yfinance/`도 생깁니다.
`.env`는 `.gitignore`에 들어 있고 앱은 이 파일을 읽기만 합니다.
같은 키가 양쪽에 있으면 환경변수가 우선합니다.

```bash
# .env
FRED_API_KEY=...
ECOS_API_KEY=...
# AI 분석을 API 키로 쓸 때만 (선택)
# ANTHROPIC_API_KEY=...
# OPENAI_API_KEY=...
# GEMINI_API_KEY=...
# 유명 투자자(SEC 13F)를 받을 때만 (선택)
# SEC_USER_AGENT="이름 이메일"
```

```bash
macro              # http://127.0.0.1:8765 를 띄우고 브라우저를 엽니다
macro --demo       # 키·네트워크 없이 예시 데이터로 화면 확인
macro --check      # 서버 없이 한 번 받아와서 출처별 상태 출력 (모두 정상이면 종료 코드 0)
```

옵션: `--port`, `--no-browser`, `--env-file PATH`, `--settings PATH`, `--version`.
서버는 항상 `127.0.0.1`에만 열리고, Streamlit 사용 통계 전송은 꺼 둡니다.

## 보기 설정

기본 화면은 개별 기업을 분석할 때 쓰는 거시 지표 63개만 보여줍니다.

- **경제 지표**: GDP, 물가(CPI·PPI·PCE), 고용, 소매판매, 산업생산. PMI는 필라델피아 연은 제조업 지수로 대신합니다.
- **통화정책**: 연준·한국은행·ECB·일본은행·인민은행 정책금리, 유로존 물가·실업률.
- **경기 주기**: 가계·기업 부채, 통화량, 경기선행지수, 장단기 금리차.
- **시장 심리**: 주가지수, VIX, 하이일드 스프레드, 소비자심리.

첫 화면의 **시장**은 세 줄에 8개씩 보여줍니다.

- **금리**: 연준 상단, 미 국채 2년·10년, 10Y−3M, 하이일드 스프레드, 한은 기준금리, 국고채 3년·10년.
- **주식**: S&P 500, 나스닥 종합, 나스닥 100, 다우, VIX, 코스피, 코스닥, 닛케이 225.
- **환율·원자재**: 달러 지수(광의), 원/달러, 엔/달러, 유로/달러, 위안/달러, WTI, 천연가스(헨리허브), 금 선물.

매크로를 더 깊게 보려면 패널별로 켭니다.

- 화면 위 **설정**(`S` 키)에서 켜거나, 패널 머리의 **+N 심화** 버튼을 누르면 그 패널의 나머지 지표가 나옵니다.
- 미 국채 수익률 곡선 차트와 기본 화면에 없는 미국 주택 패널도 설정에서 켭니다.
- 설정을 바꾸면 새로 보이는 시계열만 받아옵니다. 이미 받은 것은 다시 받지 않습니다.
- 고른 보기는 설정 파일에 저장되고, 다음에 앱을 켜면 그대로 열립니다.
  - 기본 위치: `.env`와 같은 곳, 즉 앱을 실행하는 폴더의 `finagent.settings.json`. 앱을 켜면 터미널에 경로가 표시됩니다.
  - 다른 파일을 쓰려면 `--settings PATH`
  - `.gitignore`에 들어 있어 커밋되지 않습니다.
  - 파일이 없으면 기본 보기(핵심)로 시작하고, 보기를 처음 바꿀 때 만들어집니다.
  - 파일을 읽지 못하면 기본 보기로 시작하고 화면에 알려줍니다.

```json
{
  "version": 1,
  "deep": ["labor", "housing"]
}
```

`deep`에는 전체를 펼칠 패널 id(`catalog.py`의 `PANELS`)와 수익률 곡선 차트(`curve`)가 들어갑니다.

| 보기 | 지표 | API 호출 (FRED) |
|---|---:|---:|
| 기본 (핵심) | 63 | 약 73 (45) |
| 전체 매크로 | 180 + 수익률 곡선 | 약 189 (119) |

`--check`는 보기 설정과 상관없이 모든 지표를 확인합니다.

## AI 분석 (선택)

화면 위 **AI 분석**(`A` 키)을 열고 요청을 적은 뒤 Enter(줄바꿈은 Shift+Enter)를
누르면, 모델이 지금 화면의 지표를 근거로 답합니다. 직접 실행할 때만 돌고, 쓰지
않으면 아무 일도 하지 않습니다. 답이 끝난 뒤 같은 입력창에 이어서 물으면 같은
대화로 이어집니다.

- **프리셋은 하나.** 새 대화에서 **매크로 분석** 버튼을 누르면 경기·물가·금리·
  유동성·침체 신호를 한 번에 판단해 경기 위치와 시나리오로 묶습니다. 필요한
  패널은 그 실행에만 더 받아오고 저장된 보기는 바뀌지 않습니다.
- **공급자·모델·범위.** **설정**의 AI 분석에서 고릅니다(공급자와 모델은 설정 파일에
  저장, 범위는 앱이 켜져 있는 동안만 유지). 바꾼 값은 다음 실행과 새 대화에 적용되고,
  진행 중인 대화는 시작할 때의 범위를 유지합니다.
- **범위.** 새 대화는 지금 보기(매크로 분석이 보는 패널 포함) 또는 전체 매크로의 지표
  문서로 시작합니다. 이어지는 질문은 같은 데이터 시점에 고정되고, 새로고침 뒤에는
  새 대화를 권합니다.
- **데이터 도구.** 모델은 요청에 따라 직접 데이터를 더 받아옵니다. 7개 출처에서
  시계열 찾기(`search_series`), 대시보드 지표나 출처 코드로 긴 이력 받기
  (`get_series`, 기간·주기·변환 지정), 출처별 코드 형식 보기(`source_guide`).
  한 번 실행에 12회까지 부릅니다. 받은 데이터도 메모리에만 있습니다.
- **근거와 숫자 검증.** 답의 문장마다 `[[지표 id]]` 근거가 붙고, 실행이 끝나면 답의
  숫자를 인용한 근거의 실제 값과 맞춰 봅니다. 일치는 초록, 다름은 빨강(실제 값은
  마우스를 올리면 보임), 근거에 없는 숫자는 노란 점선입니다. 근거를 누르면 그
  지표 행으로 갑니다.
- **저장하지 않음.** 대화는 앱이 켜져 있는 동안 메모리에만 있습니다. 설정 파일에는
  고른 공급자와 모델 이름만 더해집니다.

공급자는 API 키로 쓰는 세 가지입니다. 기본은 Claude입니다. API 사용량만큼 각
회사에 요금이 나갑니다.

| 공급자 | 기본 모델 | 키 (`.env`) |
|---|---|---|
| Claude API | `claude-opus-5-5` | `ANTHROPIC_API_KEY` |
| OpenAI API | `gpt-6-astra` | `OPENAI_API_KEY` |
| Gemini API | `gemini-4-argon` | `GEMINI_API_KEY` (또는 `GOOGLE_API_KEY`) |

- `uv sync`는 세 공급자의 SDK를 모두 설치합니다. 필요한 것만 설치하려면
  `uv sync --no-dev --extra claude`처럼 고릅니다(`claude`, `openai`, `gemini`,
  전부는 `llm`).
- 모델 이름은 화면에서 바꿀 수 있습니다. 비워 두면 위 기본 모델을 씁니다.
- 키는 `.env`나 환경변수에서 읽기만 하고 어디에도 저장하지 않습니다.
- 공급자 상태는 화면의 공급자 옆과 `macro --check` 출력에 나옵니다.

## 스크리닝 (선택 기능)

화면 위 **스크리닝** 페이지는 S&P 500 종목을 정해진 규칙으로 우량 추세·고평가
추세·소외 우량·저평가 개선 네 그룹에 나눕니다. 결과 위의 지도(행: 차트 강/약, 열:
비쌈 아님/비쌈)와 그 옆의 저평가 개선 칸, 또는 그룹 선택에서 그룹(각 상위
20종목)이나 전체를 고르고, 섹터로만 더 거를 수 있습니다. 차트 약이면서 비쌈인
칸은 그룹이 없습니다. 티커나 종목 이름을 누르면 기술 점수 10개 항목, 과열 표시, 결격 점검,
라벨과 업종 중앙값, EPS 추정치, 이동평균을 겹친 1년 차트가 나옵니다.

- **0단계 유동성.** 일봉 250개 이상, 주가 $5 이상인 종목 중 20일 평균 거래대금
  하위 10%를 뺍니다.
- **1단계 기술 점수(10점).** 추세 4(종가>200일선, 20일선>60일선, 60일선 상승,
  종가>20일선), 모멘텀 3(MACD>시그널, MACD>0, 50≤RSI≤70), 거래량 3(OBV 20일 상승,
  60일 오른 날 거래량>내린 날, 52주 신고가면 OBV도 60일 고점 근처, 아니면 OBV 60일
  기울기>0). 상위 20%가 차트 강, 하위 40%가 차트 약입니다(동점 포함). RSI>70,
  스토캐스틱 %K>80이면서 %K<%D, 볼린저 %B>1은 과열로 표시만 합니다.
- **2단계 결격.** FCF<0(은행은 ROE<0 또는 TCE/TA<4%, 그 밖의 금융업은 ROE<0 또는
  자기자본비율<업종 중앙값의 절반), 매출 성장 −5% 이하, 순부채/EBITDA > max(업종 중앙값×2, 3.0). 순현금은 통과,
  EBITDA≤0은 미산출, 금융업은 순부채·EV/EBITDA 기준을 쓰지 않습니다. 값이 없으면
  미확인, 음수 기준값(자본잠식 ROE, 적자 PER 등)은 해석 부적절로 두고 어느
  그룹에도 넣지 않습니다.
- **라벨.** ROE ≥ 업종 중앙값은 우수, 선행 PER 업종 내 하위 20%는 저렴, 상위 20%는
  비쌈. 경기순환 섹터(에너지, 소재, 산업재, 경기소비재)에서 선행 PER < 후행
  PER×0.6이면 정점 이익. 업종은 유동성 통과 종목 중 GICS 세부 산업이 10개
  이상이면 그 산업, 아니면 GICS 섹터입니다. 금융업은 섹터 대신 산업 그룹(은행,
  금융 서비스, 보험)으로 묶어 은행을 결제·거래소 회사와 비교하지 않습니다. 중앙값은
  S&P 500 안에서 구합니다.
- **TCE/TA.** 유형 보통주자본 ÷ 유형 총자산. Yahoo 분기 재무상태표의
  TangibleBookValue(보통주자본 − 영업권·무형자산, 우선주 제외) ÷ (TotalAssets −
  GoodwillAndOtherIntangibleAssets)이고, 값이 없으면 미확인입니다.
- **3단계 그룹.** 우량 추세는 차트 강·결격 없음·ROE 우수·비쌈 아님, 고평가 추세는
  차트 강·결격 없음·비쌈, 소외 우량은 결격 없음·ROE 우수·저렴·차트 약, 저평가
  개선은 결격 없음·우량 추세 아님·(선행 PER 또는 EV/EBITDA 업종 하위 20%)·FY1 EPS
  컨센서스가 90일 전 이상·30일 하향 ≤ 상향·기술 점수 3–6입니다. 저평가 개선은
  MACD>시그널, 52주 고점 대비 −20% 이내, 공매도 비율 5% 이상의 개수 순입니다.
  기술 점수와 재무는 합산하지 않습니다.
- **계산.** 지표는 수정주가 일봉(시가·고가·저가에 수정종가/종가 비율을 곱함)으로
  구합니다. RSI 14일과 ATR 14일은 Wilder 평활, MACD 12/26/9 EMA, 볼린저 20일
  ±2σ(모표준편차), 스토캐스틱 14/3/3. 52주 신고가는 종가 ≥ 252일 고가×0.98, OBV
  고점 근처는 60일 범위의 5% 이내입니다. 매출 성장은 직전 회계연도 대비 연간
  성장입니다(Yahoo가 분기 재무를 5분기만 줘서 TTM 전년 대비를 구할 수 없음).
- **데이터.** 구성 종목과 GICS 섹터·세부 산업은 위키백과 "List of S&P 500
  companies"에서, 시세·재무·EPS 추정치는 yfinance로 Yahoo Finance에서 받습니다.
  yfinance는 Yahoo의 공식 API가 아닙니다. 개인 용도로만 쓰고, 예고 없이 막히거나
  요청이 제한될 수 있습니다.
- **수동 갱신.** 페이지를 열 때는 저장된 파일만 읽습니다. **갱신**을 누르면
  시세는 새 날짜만(7일 겹쳐 받아 분할·배당 조정이 바뀐 종목은 전체를 다시),
  추정치는 하루 1회, 재무는 분기 1회, 구성 종목은 30일마다 받습니다. 미국 장
  마감(뉴욕 17시) 전에는 그날 일봉을 받지 않습니다. 처음 갱신(또는 새 분기의 첫
  갱신)은 15분 안팎, 그 밖에는 5분 안팎 걸립니다. Yahoo가 요청을 막으면 받은
  만큼 저장하고, 다음 갱신이 이어서 받습니다.
- **저장.** 보기 설정 파일과 같은 폴더(기본은 앱을 실행한 폴더)의 `data/screen/`에
  `universe-YYYY-MM-DD.csv`(구성 종목), `prices.parquet`(일봉, 약 2년),
  `fundamentals-YYYY-Qn.csv`(재무), `estimates-YYYY-MM-DD.csv`(EPS 추정치)를 쓰고,
  yfinance 캐시는 `data/screen/.yfinance/`에 둡니다. `data/`는 `.gitignore`에
  들어 있습니다.
- **설치.** `uv sync`가 함께 설치합니다. 개발 의존성 없이 설치했다면
  `uv sync --extra screen`. 패키지가 없으면 페이지에 설치 방법이 나옵니다.
  `--demo`에서는 갱신하지 않습니다.
- **한계.** 상위 20%·하위 40%·결격 3개·은행 TCE/TA 4% 같은 커트라인은 백테스트
  없이 정한 값입니다.
  재무는 Yahoo 단일 출처라 일회성 항목에 약하고, 공매도 비율은 약 2주 늦습니다.
  기술 신호는 조건부 관찰이지 예측이 아닙니다. 제외되었거나 받지 못한 종목은 표
  아래에 이유와 함께 나옵니다.

## 포트폴리오 (선택 기능)

화면 위 **포트폴리오** 페이지에 내가 한 거래(날짜, 티커, 매수·매도, 수량, 가격,
수수료)를 적으면 보유 종목, 평가손익·실현손익, 수익률, 위험 지표를 보여줍니다.
포트폴리오는 여러 개 만들 수 있고, 거래는 목록에서 골라 지웁니다. 그날 보유
수량보다 많은 매도는 받지 않습니다. 티커와 날짜를 넣으면 가격 칸에 그날(없으면
직전 거래일) 종가가 미리 들어가고, 고쳐 쓸 수 있습니다. 거래마다 메모(선택,
200자)를 남길 수 있습니다. 투자 조언이 아니며, 시뮬레이션은 과거
수익률을 다시 뽑아 본 결과일 뿐 예측이 아닙니다.

- **종목과 통화.** 미국 종목(`AAPL`, `BRK-B`)은 달러, 한국 종목(`005930.KS`,
  `.KQ`)은 원화로 적습니다. 다른 거래소 종목은 받지 않습니다. 포트폴리오마다
  기준통화(KRW 기본, USD)를 고르고 원·달러 환율(`KRW=X`)로 환산합니다. 외화
  거래는 거래일 환율, 평가는 최근 환율을 써서 현지 수익률과 기준통화 수익률의
  차이를 환율 효과로 보여줍니다.
- **손익.** 원가는 이동평균법(수수료 포함)입니다. 매도마다 실현손익이 남고, 전량
  매도한 종목도 실현손익, 종목별 손익, 누적 성과에 계속 들어갑니다. 총손익은
  실현손익과 평가손익의 합, 총수익률은 누적 매수금액 대비입니다. 시간가중수익률
  (TWR)과 금액가중수익률(MWR, XIRR)은 기간이 1년 미만이면 연환산하지 않습니다.
  S&P 500, KOSPI와 둘을 전날 한국·미국 비중으로 섞은 혼합 벤치마크(배당 제외
  가격지수, 기준통화)와 비교하고, 환율 효과(현지·환율·교차항), 타이밍 차이
  (MWR − TWR)와 첫날 구성을 그대로 둔 무매매 비교를 보여줍니다. 운과 시점이 섞인
  값이며 실력을 뜻하지 않습니다.
- **위험지표·상관·분산.** 수정 종가 일간 수익률(6M/1Y/3Y)로 변동성, 최대 낙폭과
  그 날짜, 고점 아래 기간, 샤프 지수와 95% 신뢰구간(Mertens 2002), PSR·MinTRL
  (Bailey–López de Prado 2012, 252일 미만은 기간 부족)을 계산합니다. 무위험수익률은
  원화 CD 91일(ECOS), 달러 ^IRX이고 없으면 0입니다. **고급**에 소르티노·칼마·얼서·
  오메가·CDaR·추적오차·정보비율이 있습니다. 상관은 한국·미국 종가 시차를 보정한
  공분산에 Ledoit–Wolf(2004) 축소를 쓰고, 베타는 Welch와 Dimson(1979, 한국
  종목), 분산은 오일러 위험 기여·분산 비율·유효 종목 수입니다. **스타일 분석**
  (Sharpe 1992)은 버튼을 눌러야 비교 지수(ETF·지수 11개)를 받습니다.
- **시뮬레이션·VaR·스트레스.** 몬테카를로는 Politis–Romano(1994) 정상
  부트스트랩(5,000경로, 평균 수익 0, 선택하면 지금 변동성 반영 FHS)이며 10% 이상
  손실 경로 비율, 기간 중 낙폭과 전고점 회복 기간을 보여줍니다. VaR·ES는 역사적·
  FHS 95/97.5/99%(최소 250/400/1,000일, 아니면 표본 부족), ES 97.5%의 범위,
  1개월 VaR 두 방식, 종목별 ES 기여, 95% 사후검정(Kupiec 1995, Christoffersen
  1998, Basel 신호등, 500일 이상)입니다. 스트레스는 1987년부터 11개 과거 구간을
  지금 보유분에 재현(구간 끝·최악·환율 몫, 구간 자료가 없는 종목은 자기 지수 ×
  1 쪽으로 당긴 베타)하고, 한국발·미국발·환율 가상 충격,
  −30% 손실에 필요한 지수 하락폭, 주간 난기류(Kritzman–Li 2010)를 보여줍니다.
  계산 방법은 페이지의 **방법·가정**에 있습니다. 계산 결과는 거래·가격 파일·기간이
  바뀔 때까지 메모리에만 보관합니다.
- **가격.** yfinance(Yahoo Finance 비공식 데이터)로 2007년부터의 일별 종가와 수정
  종가를 받습니다. S&P 500·KOSPI·원/달러는 스트레스 구간용으로 1987년부터 한 번
  더 받아 두고, 2003년 이전 원/달러는 FRED DEXKOUS(키 필요)를 씁니다. 가격이 없는
  종목은 페이지를 열거나 거래를 추가하면 백그라운드에서
  한 번 받고, **가격 갱신**은 모든 종목을 다시 받습니다. 받지 못한 값은 '미확인'으로
  둡니다. 주식 분할 전의 거래는 분할을 반영한 수량과 가격으로 적습니다.
- **저장.** 보기 설정 파일과 같은 폴더의 `data/portfolio/`에 `portfolios.json`
  (포트폴리오와 거래), `close.parquet`·`adjusted.parquet`(가격), yfinance 캐시
  (`.yfinance/`)를 둡니다. 파일은 임시 파일에 쓴 뒤 바꿔 넣습니다.
- **설치.** 스크리닝과 같은 `screen` 추가 패키지를 씁니다. `--demo`에서는 가격을
  받지 않고 저장된 데이터만 보여줍니다.

### 종목 분석

포트폴리오 페이지 위의 **종목 분석**으로 바꾸면 티커 하나(Enter 또는 **분석**,
또는 보유 종목 중 선택)를 위험지표·시뮬레이션·VaR·스트레스 탭으로 봅니다. 가격이
없는 티커는 처음 고를 때 지수·환율과 함께 한 번 받아 같은 `data/portfolio/` 가격
파일에 저장합니다. 계산은 내 포트폴리오와 같은 방법을 비중 100%에 쓰고(금액은
1주 기준, 기준통화는 종목 통화가 기본이며 KRW/USD로 바꿀 수 있음, 벤치마크는
한국 종목 KOSPI·그 밖 S&P 500), 한 종목에서 뜻이 없는 상관·분산 비율·유효 종목
수·종목별 ES 기여·주간 난기류는 뺍니다.

**넣으면 어떻게 되나** 탭은 고른 포트폴리오 평가액의 1–30%를 이 종목에 넣고 기존
보유분을 비중대로 줄였을 때(이미 보유하면 지금 비중에 더함) 변동성·베타·분산
비율·ES 97.5%, 몬테카를로 결과, 과거 구간 재현을 추가 전후로 나란히 보여줍니다.
보유 종목과 이 종목이 모두 값이 있는 날의 일간 수익률을 포트폴리오 기준통화로 맞추고
(자료가 짧으면 그만큼 짧은 기간), 시차 보정·Ledoit–Wolf 공분산을 씁니다. 상관이
σp/σc보다 낮으면 조금 더할 때 변동성이 줄어든다는 기준, 같은 날들로 다시 계산한
증분 ES, 추가 후 이 종목의 ES 기여를 함께 보여주며, 몬테카를로는 추가 전후에 같은
재표본 날짜를 씁니다. 결과를 설명할 뿐 비중을 권하지 않습니다.

### 유명 투자자 (SEC 13F)

포트폴리오 페이지 위의 **유명 투자자**로 바꾸면 버핏(Berkshire Hathaway), 애크먼,
버리, 리루, 클라만, 드러켄밀러, 테퍼, 달리오(Bridgewater), 로브, 아인혼(DME
Capital, 옛 Greenlight)의 13F 보유 종목을 보유·수익률·위험지표·상관·분산·
시뮬레이션·VaR·스트레스·비교 탭으로 봅니다. **CIK 추가**로 13F-HR을 내는 다른
운용사를 더할 수 있습니다. 투자 조언이 아니며, 13F는 미국 상장 주식 롱 포지션만
보여줍니다. 공매도·옵션·채권·현금·분기 중 매매는 빠져 있어 실제 펀드 수익률과
다릅니다.

- **출처.** SEC EDGAR의 13F-HR·13F-HR/A 정보표(최근 8개 분기), CUSIP → 티커는
  OpenFIGI(키 없이, 요청당 10건·분당 25회 한도), 섹터와 가격은 yfinance입니다.
  가격은 포트폴리오와 같은 `data/portfolio/` 가격 파일에 함께 저장합니다.
- **User-Agent.** SEC는 연락처가 담긴 User-Agent를 요구합니다. `.env`에
  `SEC_USER_AGENT="이름 이메일"`을 넣어야 받습니다. 이 값은 SEC 요청에만 씁니다.
  없으면 화면에 한 줄 안내만 나오고 아무것도 받지 않습니다.
- **받는 때.** 투자자를 처음 열 때 저장된 자료가 없으면 한 번, 그리고 **갱신**을
  누를 때만 백그라운드에서 받습니다(한 번에 한 투자자, SEC 요청 사이 0.15초).
  이미 받은 제출 문서는 다시 받지 않습니다.
- **계산.** 같은 CUSIP의 여러 행은 합산하고, 풋·콜 옵션과 원금(PRN) 단위 행은
  따로 셉니다. 2023-01-03 이후 제출분은 달러, 이전은 천 달러 단위입니다. 정정
  중 RESTATEMENT는 분기를 바꾸고 NEW HOLDINGS는 더합니다. 복제 수익률은
  제출일(휴장이면 다음 거래일) 종가에 보고 비중으로 사서 다음 제출까지 들고 있는
  경우가 기본이고, 분기 말에 샀다고 본 이론값은 공개 전 정보를 쓴 값이라 회색으로만
  보여줍니다. 보고 비중이 큰 10종목만(보고 가치 비중 또는 같은 비중) 사는 복제도
  고를 수 있고, 리밸런싱마다 회전율과 종목 수, 최근 보고의 분기 말 이후 경과일을
  보여줍니다. USD 기준이며, 원화 포트폴리오는 일별 환율로 환산합니다. 티커를
  못 찾았거나 가격이 없는 종목은 계산에서 빼고 그 비중을 '가격 미연결 비중'으로
  표시합니다.
- **위험 계산.** 복제의 일간 수익률과 지금 비중(마지막 매수 뒤 가격대로 변한
  비중)에 내 포트폴리오와 같은 방법을 씁니다: 샤프 신뢰구간·PSR·MinTRL, 낙폭,
  Welch 베타, Ledoit–Wolf 상관, 몬테카를로, VaR·ES와 사후검정, 과거 구간 재현·가상
  충격, 스타일 분석. 무위험수익률은 ^IRX, 벤치마크는 S&P 500입니다. 투자자·내
  포트폴리오의 상관은 일간 수익률에 한국·미국 종가 시차 보정과 Ledoit–Wolf 축소를
  씁니다. 투자자 둘 이상을 나란히 볼 때는 샤프를 경험적 베이즈로 축소한 값과, 여럿
  중 최고값이 운으로 나올 수준을 넘는지(DSR)를 함께 보여줍니다. 보유 겹침은 내
  포트폴리오의 미국 주식 부분만 비교하며(1 − 액티브 셰어) 실력 지표가 아닙니다.
- **저장.** `data/investors/`에 투자자별 `<CIK>/filings.json`과 제출 문서별
  `<CIK>/<접수번호>.json`, `cusips.json`(티커 연결, 못 찾은 것도 날짜와 함께 두고
  30일 뒤 다시 조회), `sectors.json`, 추가한 CIK 목록 `investors.json`, yfinance 캐시(`.yfinance/`)를
  둡니다.
- **한계.** 13F는 분기 보고이며 분기 말 뒤 최대 45일에 제출됩니다. 미국 상장 롱
  포지션만 담고 공매도·현금·채권·해외 주식은 없으며, 기밀 처리된 종목은 빠졌다가
  나중에 공개될 수 있습니다. 인수·상장폐지로 가격 기록이 없는 종목은 빠지고(생존
  편향), 직전 분기 대비 변동은 주식 분할을 조정하지 않습니다.

## 데이터 원칙

매크로 대시보드의 원칙입니다. 스크리닝과 포트폴리오(선택 기능)는 위에 적은 대로
예외입니다.

- **공공·공개 출처.** 아래 7개 출처의 API에서 받는 시계열을 씁니다. 공식 통계뿐
  아니라 같은 출처가 제공하는 나우캐스트(GDPNow), 주가지수(S&P 500, 나스닥,
  다우, 닛케이 225, 코스피), 민간 지수(미시간대 소비자심리, Case-Shiller, ICE
  스프레드)도 씁니다. 제3자 저작권 시계열은 지표 이름 옆에 © 출처를 적습니다.
  예외는 금 선물(`GC=F`) 하나로, FRED에 일별 금 시세가 없어 yfinance(Yahoo
  Finance 비공식 데이터)로 받습니다. yfinance는 `screen` 추가 의존성이라 `uv sync`가
  함께 설치합니다. 없으면 금 타일은 —로, 출처 점검의 Yahoo는 키 없는 출처처럼
  회색으로 나오고 나머지는 그대로입니다.
- **FOMC 경제전망(SEP).** 연방기금금리·GDP·실업률·PCE 물가의 위원 중앙값을 연도별로
  보여주고, FRED의 발표 시점별 값(ALFRED)으로 직전 발표 대비 변화를 함께 표시합니다.
- **저장하지 않음.** 받은 시계열은 앱이 켜져 있는 동안 메모리에만 있고 디스크에
  쓰지 않습니다. 대시보드가 쓰는 파일은 보기 설정 파일(패널 id 목록과 고른 AI
  공급자) 하나뿐이고, 금 시세를 받는 yfinance가 자체 캐시(시간대·쿠키)를
  `data/macro/.yfinance/`에 둡니다. 스크리닝 데이터는 `data/screen/`에만, 포트폴리오의 거래
  기록과 가격은 `data/portfolio/`에만, 13F 자료는 `data/investors/`에만 씁니다.
- **수동 갱신.** 앱을 시작한 뒤 처음 화면을 열 때 한 번, 그리고 화면의 새로고침
  버튼을 누를 때만 받아옵니다. 타이머로 자동 갱신하지 않습니다.
- 키가 없거나 응답하지 않는 출처는 화면에 따로 표시되고, 나머지 지표는 그대로
  나옵니다. 일시적 오류(시간 초과, 연결 실패, 5xx)는 한 번 다시 시도합니다.
- FRED는 키당 분당 약 120회까지 받습니다. 기본 화면은 한 번 갱신에 약 45회,
  모든 패널을 켜면 약 120회를 부르므로 그때는 새로고침을 1분에 한 번 정도로 하세요.

## 지표 추가

모든 지표는 `src/finagent/catalog.py` 한 파일에 있습니다. 패널의 튜플에 한 줄을
추가하면 됩니다.

```python
fred("us_mfg_tcu", "제조업 설비가동률", "MCUMFN", "M", PCT1),
```

`--demo`와 테스트가 새 지표도 받을 수 있도록 `src/finagent/demo.py`의 해당 출처
표에 가짜 시계열 한 줄을 함께 추가합니다. 변환은 `"level"`, `"yoy"`, `"pct"`(전기 대비 %), `"diff"`, `"sum12"`(12개월 합)
중에서 고릅니다. 상단 줄에 넣을 지표는 `TAPE`에 id를 추가합니다.
기본 화면에도 보일 지표는 `CORE`에 id를 추가합니다. 나머지는 그 패널의 심화
보기를 켰을 때만 보입니다.

## 개발

```bash
uv run ruff check .
uv run ruff format --check .
uv run basedpyright
uv run pytest -q
```

화면은 `src/finagent/app.py`(Streamlit 스크립트)이고, 숫자 표기와 분석 로그 같은
화면용 텍스트는 `src/finagent/display.py`에 있습니다. 개발 중에는
`uv run streamlit run src/finagent/app.py -- --demo`로 띄우면 파일을 고친 뒤
화면에서 바로 다시 실행할 수 있습니다.

테스트는 실제 API를 부르지 않습니다. `src/finagent/demo.py`가 각 출처의 실제 응답
형식을 흉내 낸 가짜 응답을 만들고, `--demo`와 테스트가 이것을 씁니다. 이 저장소를
만든 환경에서는 데이터 API에 접속할 수 없어서 실제 응답으로는 확인하지 못했습니다.
처음 실행할 때 `macro --check`로 출처별 상태를 확인하세요.
